# 化学文献抽取平台：四人分工

项目初期讨论稿。需求、功能优先级和接口由四人共同商议，以下为整个项目的主要分工，成员姓名后续填写。

## 项目功能

- 上传和管理论文，创建抽取任务并查看状态。
- 展示样品和提取字段，支持字段与 PDF 原文相互定位。
- 核对、修改、保存和导出结果。
- 搜索字段和论文内容，通过 RAG 提供带来源的回答。
- 提供网站内常驻 AI 面板，支持围绕论文提问。

## 四人分工

| 成员 | 负责方向 | 主要内容 |
|---|---|---|
| A：姓名待填 | 文献与任务前端 | 论文上传、文献列表、任务状态、失败重试、历史结果入口 |
| B：姓名待填 | 复核与 AI 前端、风格设计 | PDF 阅读、字段表格、双向定位、修改与导出交互、搜索页面、常驻 AI 面板、前端部署 |
| C：姓名待填 | Java 后端 | 后端框架、文件和数据存储、异步任务、结果及修改接口、字段筛选、对接 Agent/RAG、后端部署 |
| D：姓名待填 | Agent、RAG 与问答 | 理解并接入现有 Python Agent、输出适配、论文分块与检索、带引用问答、抽取和检索效果检查 |

A、B 共用前端工程并统一组件和风格。C 提供网站接口，D 提供抽取、检索和回答能力。接口联调、测试和文档由对应模块负责人完成，最终演示全员参与。

## 实现约定

- 架构：网页 → Nginx → Java 后端 → Python Agent / RAG。保留现有 Agent，不重写为 Java。
- 双向定位先做到页码和引文，精确高亮后续再评估。
- 字段搜索用于筛选结构化数据，RAG 用于检索论文内容并辅助回答；AI 面板展示回答来源。
- 前端先做原型再实现：可用 `visualize:visualize` 辅助交互设计；若采用 Sites 建站，再使用 `sites:sites`。Nginx 用于网页部署和请求转发。
